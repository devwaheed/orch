How a job breaks down
A job is your goal. The orchestrator splits it into runs; each run gets a session and, if it edits code, a worktree.
Session = the agent’s conversation and CLI session id, so the run can be resumed.   Worktree = its own copy of the repo on its own branch, so agents never overwrite each other. Read-only runs need no worktree.
