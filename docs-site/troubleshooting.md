# Troubleshooting

Diagnose system issues with orch doctor, handle engine interruptions, create sanitized bug reports, and resolve common problems.

## Run doctor

Run `orch doctor` in your terminal to verify your operating system, agent CLI installations, engine status, and profile permissions:

```bash
orch doctor
```

- If doctor reports an error, it prints a specific **Fix** recommendation. Follow the instruction and re-run the check.
- To verify that agent accounts remain strictly isolated from each other on your machine, run:

```bash
orch doctor --sign-in-twice
```

This creates temporary throwaway profiles for each agent, verifies that tokens stay separated, and confirms that shared skills are accessible.

## The engine keeps stopping

The engine host process runs Claw Orchestrator. If the engine process terminates unexpectedly, orch restarts it automatically with an exponential backoff schedule (1s, 2s, 5s, 10s, then every 30s).

While restarting, the status bar shows an amber indicator with **engine restarting**.

If the engine fails 5 times within 10 minutes, orch displays a persistent notification bar under the title bar:
**The engine keeps stopping.** with two action buttons:

- **Restart engine**: attempts an immediate manual restart of the engine host.
- **Report a problem**: opens the bug report dialog.

## Report a problem…

When you encounter unexpected behavior or errors, create a sanitized bug report archive.

You can open the report dialog from several places:

- Select **Help → Report a problem…** from the application menu.
- Open the command palette (⌘K on macOS, Ctrl+K elsewhere) and choose **Report a problem…**.
- Click **Report a problem** on the engine failure bar or a crash notification.
- Run `orch bug-report` in your terminal (or specify `orch bug-report --out <folder>`).

### What happens when you create a report

1. The dialog displays: `orch will save these files to a zip on your computer. Nothing is sent anywhere.`
2. Click **Save report**.
3. orch saves a zip file named `orch-bug-report-<YYYYMMDD-HHMMSS>.zip` into `~/.orch/bug-reports/` (or your `--out` path).
4. After saving, you can click:
   - **Show in folder**: reveals the zip file in your system file manager.
   - **Open GitHub issue**: opens the GitHub issue creation page in your browser with your operating system and orch version prefilled so you can attach the zip.

### What is included in the zip

The bug report zip contains exactly these files:

- `versions.json`: versions of orch, the engine, Node.js, and your operating system.
- `doctor.json`: the complete report generated by `orch doctor`.
- Recent logs: the last 3 days of logs from `~/.orch/logs/`, with tokens, keys, passwords, and environment values redacted.
- `accounts.yaml`: your account configuration with email addresses masked.
- `specs.yaml`: your spec queue configuration (if present in the active repository).

> A bug report never contains transcripts, repository code, tokens, private keys, environment variables, or agent profile directories. Archives older than 30 days are automatically deleted when orch starts.

## Common problems

### Account shows "Limited"

- When an account exhausts its usage limit, orch pauses the active run without data loss.
- In [work.md](work.md), click **Resume now on [agent] · [account]** to hand off to another available account.
- In [accounts.md](accounts.md), you can also click **Re-login** if the agent's authentication token expired.

### Antigravity allows only one account

- On macOS and Windows, Antigravity stores logins in the operating system's shared credential store (macOS Keychain or Windows Credential Manager). orch restricts Antigravity to a single account on these systems to prevent silent account switching. Linux supports multiple accounts.

### Specs queue fails to start

- Run `orch specs check` in your terminal to inspect spec files.
- Each spec file in `docs/specs/` requires valid YAML front matter with a numeric `id` and title.
- If importing BMAD stories without front matter, run `orch specs init` to add front-matter skeletons.

## Uninstalling orch

To remove orch completely from your system:

```bash
orch uninstall
```

- orch prompts for confirmation before deleting anything. Use `orch uninstall --yes` to skip the prompt.
- This command removes `~/.orch/` (or `%USERPROFILE%\.orch`), including the database, logs, and account profile folders.
- It never touches your git repositories, worktrees outside `~/.orch/`, or your agents' personal configuration folders.
